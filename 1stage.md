# Этап 1. Пилотный RAG-механизм: техническая реализация

Инструкция для Claude Code. Выполняй шаги по порядку. В конце каждого шага проверь критерий готовности. Там, где написано **«Чекпоинт»**, остановись и покажи результат пользователю, прежде чем идти дальше.

## 0. Контекст и цель

Строим ИИ-наставника, который отвечает студенту **строго по загруженным материалам курса**, со ссылкой на источник. Если ответа в материалах нет, наставник говорит об этом прямо. Этап 1 — минимальный рабочий RAG-конвейер на пилотных документах и прогон по контрольному набору из 22 вопросов с фиксацией результатов для анализа.

**Что входит в этап 1:**
- парсинг трёх PDF с сохранением метаданных (документ, раздел, страница);
- нарезка на фрагменты, эмбеддинги, локальный векторный индекс;
- ответ локальной LLM (Ollama) по найденным фрагментам со ссылками `[n]`;
- прогон 22 контрольных вопросов, сохранение полного ответа, найденных фрагментов и метаданных, автоматические проверки и отчёт по шаблону;
- прогон «без RAG» (голая модель) для сравнения.

**Что НЕ входит в этап 1** (это этап 2, не делай этого сейчас): FastAPI, PostgreSQL/pgvector, реранкер, гибридный поиск, веб-интерфейс, Docker. При этом код пиши через порты и адаптеры, чтобы на этапе 2 заменить хранилище и добавить компоненты без переписывания логики.

## 2. Окружение

### Управление проектом — только через `uv`

Проект целиком ведётся через `uv`. **Запрещено:** `pip install`, `python -m venv`, `requirements.txt`, ручная активация виртуального окружения, запуск через голый `python`/`pytest`. Всё — через `uv`.

**Шаг 2.0. Инициализация** (выполнить в корне проекта):
```bash
uv python install 3.12
uv init --app --name mentor --python 3.12 --no-readme
uv python pin 3.12
```
Если `uv init` создал `main.py` или `hello.py`, удали этот файл: точка входа — `mentor/__main__.py`.

Зависимости добавляются **только** через `uv add`:
```bash
uv add pymupdf numpy httpx pyyaml pydantic pydantic-settings typer rich
uv add --dev pytest ruff
```

В `pyproject.toml` настрой пакет `mentor` в корне (без `src/`) и консольную команду:
```toml
[project.scripts]
mentor = "mentor.__main__:app"

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[tool.hatch.build.targets.wheel]
packages = ["mentor"]

[tool.uv]
package = true
```
Затем выполни `uv sync`. После этого все команды проекта запускаются как `uv run mentor <команда>`, тесты — `uv run pytest`, линтер — `uv run ruff check .` и `uv run ruff format .`.

`uv.lock` коммитится в репозиторий. Второй участник команды разворачивает проект одной командой `uv sync`.

В `.gitignore`: `.venv/`, `data/`, `runs/`, `__pycache__/`.

Проверка шага 2.0: `uv run mentor --help` выводит список команд (`ingest`, `ask`, `eval`, `report`), хотя бы как заглушки.

### Ollama
- Ollama ставится нативно (не в Docker), API на `http://localhost:11434`. На Mac Docker не даёт контейнеру доступа к GPU Apple Silicon, и модели работают только на CPU.
- Модели:
  - эмбеддинги: `bge-m3` (мультиязычная, документы и вопросы на русском);
  - LLM на Mac M4: `qwen3:8b`, плюс `qwen3:30b-a3b`, если памяти 24 ГБ и больше;
  - LLM на ПК с RTX 2060 (6 ГБ VRAM): `qwen3:4b`, `qwen3:8b`.
- Код должен одинаково работать на macOS и Windows: пути только через `pathlib`, кодировка файлов везде `utf-8`.

**Шаг 2.1.** Проверь, что Ollama запущена (`GET /api/tags`) и нужные модели скачаны. Если моделей нет, выведи пользователю точные команды `ollama pull ...` и не продолжай, пока они не появятся.

## 5. Домен и порты

`domain.py` (dataclasses или pydantic):
- `Block`: `doc_id`, `text`, `page` (с 1), `section` (например `"9.3.1"` или `null`), `section_title`, `kind` (`text` | `code`).
- `Chunk`: `chunk_id` (`P9-0012`), `doc_id`, `doc_title`, `section`, `section_title`, `page_from`, `page_to`, `text` (без префикса), `text_for_embedding` (с префиксом заголовка).
- `ScoredChunk`: `chunk` и `score`.
- `Citation`: `n`, `chunk_id`, `doc_id`, `doc_title`, `section`, `page_from`, `page_to`.
- `Answer`: `question`, `answer_text`, `refused`, `citations`, `invalid_citation_numbers`, `retrieved: list[ScoredChunk]`, `top_score`, `latency_ms`, `model`, `mode` (`rag` | `no_rag`).

`ports.py`:
```python
class DocumentLoader(Protocol):
    def load(self, doc: DocumentSpec) -> list[Block]: ...
class Chunker(Protocol):
    def split(self, doc: DocumentSpec, blocks: list[Block]) -> list[Chunk]: ...
class Embedder(Protocol):
    def embed(self, texts: list[str]) -> np.ndarray: ...   # L2-нормированные векторы
class VectorStore(Protocol):
    def add(self, chunks: list[Chunk], vectors: np.ndarray) -> None: ...
    def search(self, vector: np.ndarray, top_k: int) -> list[ScoredChunk]: ...
    def save(self) -> None: ...
    def load(self) -> None: ...
class LLM(Protocol):
    def chat(self, system: str, user: str) -> str: ...
```
Сервисы зависят только от портов. Адаптеры собираются в одном месте (фабрика в `__main__.py` или `config.py`).

## 6. Шаг 1: парсинг PDF (`PyMuPdfLoader`)

1. Читай PDF постранично через `pymupdf` (`page.get_text("dict")` или `"blocks"`), сохраняя номер страницы (с 1, как в методике тестирования).
2. **Удаление колонтитулов.** Это сохранённые из браузера страницы документации, поэтому на них могут быть дата и время, URL `docs.python.org`, счётчик вида `3/12`, навигация сайта. Строки, которые повторяются на 50% страниц и больше, удаляй. Отдельно регулярками удаляй URL-строки, счётчики страниц и строки вида `дд.мм.гггг, чч:мм`.
3. **Определение разделов.** Заголовок раздела — строка, начинающаяся с номера вида `^(\d+(?:\.\d+){0,3})\.?\s+\S`, где **первое число равно `chapter` документа** (4, 5 или 9), а глубина не больше 4. Защита от ложных срабатываний: не считай заголовком строки внутри блоков кода (`>>>`, `...`, отступы) и строки длиннее 120 символов. Каждому блоку присваивай текущий `section` и `section_title`. Текст до первого подзаголовка получает `section` = номер главы (например `"9"`).
4. Если в документе есть оглавление (повтор списка заголовков в начале), не используй его строки для определения разделов. Фактическое начало раздела — первое вхождение заголовка **после** оглавления. Определи это по факту, посмотрев на файлы.
5. Строки примеров кода (`>>>`, `...`, вывод интерпретатора) помечай `kind = code` и не разрывай при нарезке, если это возможно.
6. Склеивай переносы строк внутри абзацев, а дефисные переносы (`функ-\nция`) соединяй.
7. Сохраняй результат для ручной проверки в `data/parsed/<doc_id>.md`: перед каждым блоком комментарий `<!-- page N | section X.Y -->`, затем текст.

**Чекпоинт 1.** Покажи пользователю:
- для каждого документа: число страниц, найденные разделы (номер, заголовок, страница начала);
- по 2 фрагмента `data/parsed/*.md` из каждого документа;
- сверку с методикой: раздел 9.3.1 должен начинаться на стр. 5 в P9, раздел 4.3 — на стр. 2 в P4, раздел 5.5 — на стр. 8 в P5 (±1 страница допустимо, расхождения нужно объяснить).

Если разделы определяются плохо, сначала исправь парсер. Остальное без этого бессмысленно.

## 7. Шаг 2: нарезка (`SectionChunker`)

1. Группируй блоки по `section`. Один раздел — один чанк, если он короче `max_chars`.
2. Длинный раздел режь по границам абзацев и кодовых блоков с перекрытием `overlap_chars`. Посреди кодового примера не режь, если он короче `max_chars`.
3. Чанки короче `min_chars` склеивай с соседним **в пределах того же документа**, предпочтительно того же родительского раздела. `section` получившегося чанка — раздел первого блока, а `page_from`/`page_to` охватывают оба.
4. `text_for_embedding` = `"{doc_title} › {section} {section_title}\n\n{text}"`, если `heading_prefix: true`.
5. Сохраняй `data/index/chunks.jsonl` (все поля `Chunk`).

Тесты (`tests/test_chunker.py`): чанк не превышает `max_chars + допуск`; не теряется текст (сумма текстов без перекрытий покрывает исходный); метаданные страниц корректны; кодовый блок не разрезан.

Выведи статистику: число чанков на документ, средняя, минимальная и максимальная длина.

## 8. Шаг 3: индекс (`OllamaEmbedder` + `NumpyVectorStore`)

1. Эмбеддинги: `POST {base_url}/api/embed` с телом `{"model": embed_model, "input": [...]}`, пакетами по 16–32 текста. Результат L2-нормируй. У `bge-m3` префиксы `query:`/`passage:` **не нужны**.
2. `NumpyVectorStore`: векторы в `data/index/vectors.npy`, метаданные в `chunks.jsonl`, параметры индекса в `manifest.json` (модель эмбеддингов, размерность, sha256 исходных PDF, конфиг нарезки, дата). Поиск: скалярное произведение и top_k.
3. При загрузке индекса сверяй `manifest.json` с текущим конфигом и хешами PDF. При расхождении выводи понятную ошибку «пересоберите индекс: `uv run mentor ingest`».
4. CLI: `uv run mentor ingest` — полный цикл: парсинг → нарезка → эмбеддинги → сохранение.

**Защита от утечки эталонов** (`tests/test_index_isolation.py`, запуск `uv run pytest`):
- в `manifest.json` и `chunks.jsonl` присутствуют только `doc_id` из `{P4, P5, P9}`;
- ни один путь в манифесте не указывает на `Otsenka_raboty_sistemy.pdf` или `questions.yaml`;
- ни один чанк не содержит маркеров методики: «Эталонный ответ», «Критерий ошибки», «Провокационный вопрос», «Ожидаемое поведение»;
- `ingest` падает с понятной ошибкой, если в конфиге базы знаний указан файл из списка запрещённых (`Otsenka_raboty_sistemy.pdf`, `mentor/eval/questions.yaml`).

Эталонный ответ (`reference`) используется только в `checks.py` и `report.py`. В `services/answer.py` его передавать нельзя, сервис о нём не знает.

Smoke-проверка после индексации: поиск по запросу «метод __init__» должен вернуть в top-3 чанк из P9 раздела 9.3.2, а по запросу «range конечная точка» — чанк из P4 раздела 4.3. Выведи top-3 с `score`, документом, разделом и страницами.

## 9. Шаг 4: генерация ответа (`AnswerService`, `OllamaLLM`)

### Вызов Ollama
`POST {base_url}/api/chat`, `stream: false`, сообщения `system` и `user`, `options: {num_ctx, temperature}`, `think: false`.
- **`num_ctx` передавай явно.** Иначе Ollama молча обрежет контекст до значения по умолчанию.
- Если модель не поддерживает параметр `think` (ошибка API), повтори запрос без него. Если в ответе всё равно есть `<think>...</think>`, вырежи этот блок.

### Формат контекста (user-сообщение)
```
Фрагменты материалов курса:

[1] Р9. Классы — раздел 9.3.2 «Объекты экземпляров», стр. 6
<текст чанка>

[2] Р4. Дополнительные инструменты управления потоком выполнения — раздел 4.3 «Функция range()», стр. 2
<текст чанка>

Вопрос студента: <вопрос>
```

### Системный промпт (дословно, вынести в `mentor/prompts.py`)
```
Ты — ассистент-наставник учебного курса. Отвечай на вопрос студента ТОЛЬКО на основе пронумерованных фрагментов материалов курса, приведённых в сообщении.

Правила:
1. Используй только сведения из фрагментов. Не добавляй ничего из собственных знаний, даже если уверен, что это правда.
2. После каждого утверждения ставь ссылку на номер фрагмента в квадратных скобках, например [1] или [2][3].
3. Если ответ опирается на несколько фрагментов, укажи все использованные.
4. Если во фрагментах нет информации для ответа, ответь ровно одной фразой: «В материалах курса этого нет.» — и ничего не добавляй.
5. Если информации хватает только на часть ответа, ответь на эту часть со ссылками и прямо скажи, какой части в материалах нет.
6. Отвечай на русском языке, кратко и по существу.
```

### Постобработка
- Отказ (`refused = True`), если нормализованный ответ (нижний регистр, без пунктуации) содержит `в материалах курса этого нет`.
- Ссылки разбирай регуляркой `\[(\d+)\]`, номера сопоставляй с переданными фрагментами. Номера вне диапазона записывай в `invalid_citation_numbers`.
- `top_score` — score первого найденного фрагмента. Если задан `min_score` и `top_score < min_score`, LLM не вызывается: ответ «В материалах курса этого нет.», `refused = True`.

### Режим без RAG (`mode = no_rag`)
Тот же вопрос, но без фрагментов, с системным промптом: «Ответь на вопрос студента кратко на русском языке.» Нужен, чтобы увидеть, что модель знает сама.

CLI: `uv run mentor ask "Что такое множество?" [--model qwen3:4b] [--no-rag] [--top-k 8]` печатает ответ, ссылки и найденные фрагменты (документ, раздел, страницы, score, первые 200 символов).

Тесты (`tests/test_citations.py`): разбор ссылок `[1]`, `[1][3]`, `[1, 2]` (последний формат тоже поддержи), невалидные номера, определение отказа с разной пунктуацией.

**Чекпоинт 2.** Задай через `ask` три вопроса: №5 (`__init__`), №13 (множество), №16 (провокация). Покажи пользователю ответы, ссылки и найденные фрагменты.

## 11. Шаг 5: прогон (`uv run mentor eval`)

```
uv run mentor eval [--model qwen3:8b] [--top-k 6] [--no-rag] [--only 1,5,M1] [--tag mac-m4]
```

1. Каждый вопрос задаётся **отдельно**, без истории (требование 1 методики).
2. Папка прогона: `runs/<YYYYMMDD-HHMM>_<model>_<mode>_<tag>/`, внутри:
   - `config.json` — полный эффективный конфиг, git sha (если есть), хост (`platform.node()`, ОС), версия Ollama;
   - `records.jsonl` — по строке на вопрос: `id`, `type`, `question`, `answer_text`, `refused`, `citations`, `invalid_citation_numbers`, `retrieved` (для каждого фрагмента: `chunk_id`, `doc_id`, `doc_title`, `section`, `section_title`, `page_from`, `page_to`, `score` и **полный текст**), `top_score`, `latency_ms`, `checks` (см. ниже) и пустые поля для ручной оценки `manual_score`, `manual_error_codes`, `manual_comment`.
3. Ошибку одного вопроса (таймаут, ошибка API) записывай в `error` и продолжай прогон.
4. Показывай прогресс (`rich`), в конце выводи краткую сводку.

### Автоматические проверки (`checks.py`)
Проверки — **подсказки для ручной оценки, а не итоговая оценка**. Итоговую оценку 0/1/2 ставит человек по таблицам 5 и 6 методики.

Для `main`:
- `retrieval_hit` — среди найденных есть чанк с эталонным документом и разделом;
- `retrieval_hit_page` — то же, плюс пересечение страниц;
- `gold_rank` — позиция первого эталонного чанка (или `null`);
- `has_citation` — есть хотя бы одна валидная ссылка;
- `cites_gold` — среди процитированных есть эталонный чанк;
- `refused` — ложный отказ, если `true`.

Для `provocation`:
- `refused` — `true` означает успех;
- `pass` = `refused`.

Для `multi`:
- `docs_retrieved` — какие эталонные документы найдены, `all_docs_retrieved`;
- `sections_retrieved` — какие эталонные разделы найдены, `sections_coverage` — доля;
- `docs_cited` — какие эталонные документы процитированы, `all_docs_cited`.

### Предварительные коды ошибок (`suggested_error_codes`, по таблице 7 методики)
- `R1` — `main`: `retrieval_hit = false`; `multi`: `all_docs_retrieved = false`;
- `R2` — все найденные фрагменты не из эталонных разделов (для `main`/`multi`);
- `S1` — ответ дан, не отказ, но `has_citation = false`; для `multi` — `all_docs_cited = false`;
- `S2` — есть ссылки, но ни одна не указывает на эталонный чанк, хотя эталонный чанк среди найденных был;
- `G2?` — для `provocation`: `refused = false` (модель ответила внешними знаниями); для `main`/`multi` автоматически не определяется;
- `G1` и `G2` для основных вопросов ставятся только вручную.

## 12. Шаг 6: отчёт (`uv run mentor report <run_dir> [<run_dir> ...]`)

Для каждого прогона создаются:

1. **`results.csv`** по шаблону методики, с колонками `№; Вопрос; Найденные фрагменты; Источники; Ответ LLM; Оценка; Комментарий / тип ошибки`, плюс служебные `Подсказки проверок; Предварительные коды`.
   - «Найденные фрагменты» — список `doc_id §section стр.X–Y (score)`;
   - «Источники» — процитированные документы, разделы и страницы;
   - «Оценка» и «Комментарий» пустые, их заполняет человек;
   - разделитель `;`, кодировка `utf-8-sig`, чтобы Excel открывал файл без проблем.
2. **`results.md`**:
   - шапка: модель, режим, хост, top_k, параметры нарезки, дата;
   - сводка: Hit@k по основным вопросам, доля ответов со ссылкой, доля провокаций с отказом, доля ложных отказов, покрытие документов для M1/M2, среднее и p95 время ответа;
   - по каждому вопросу: вопрос, эталон, ответ модели, ссылки, найденные фрагменты (документ, раздел, страницы, score, первые 300 символов), результаты проверок, предварительные коды.

Если передано несколько прогонов, дополнительно создаётся `runs/comparison.md`: таблица сводных метрик по прогонам и таблица «вопрос × прогон» с отметками: найден ли эталон, есть ли ссылка, отказ.

## 13. Шаг 7: матрица прогонов

Выполни (или выведи пользователю команды, если модели на другой машине):

```
uv run mentor eval --model qwen3:8b --tag <host>
uv run mentor eval --model qwen3:8b --no-rag --tag <host>
uv run mentor eval --model <вторая модель для этой машины> --tag <host>
uv run mentor report runs/*
```

Режим `--no-rag` гоняется на всех 22 вопросах. Он показывает, на какие вопросы модель отвечает без материалов: особенно важно, отвечает ли она на провокации 16–20, которые в режиме RAG должны отсекаться.

## 15. Принципы реализации

- Не усложняй: никаких фреймворков оркестрации (LangChain, LlamaIndex) — конвейер прозрачный и короткий, его нужно отлаживать по шагам.

- Каждый прогон полностью воспроизводим по `config.json` и `manifest.json`.
- Логика сервисов не знает про конкретные адаптеры: на этапе 2 `NumpyVectorStore` заменяется на pgvector, добавляются гибридный поиск и реранкер без изменения `AnswerService` и `eval`.
